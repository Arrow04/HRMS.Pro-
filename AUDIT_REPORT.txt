HRMS.Pro! — Production Readiness Audit Report
=============================================

Date: 2026-09-08
Scope: hrms_backend, hrms_react_web, hrms_mobile, hrms_tenant_hub

EXECUTIVE SUMMARY
-----------------
The project shows strong architectural foundations: FastAPI backend with
enterprise middleware, React 19 frontends with TanStack Query, and a
multi-tenant data model. However, several P0/P1 gaps must be addressed
before production deployment.

Findings are grouped by module and severity.


================================================================================
1. BACKEND (hrms_backend)
================================================================================

| Severity | Category | Finding | File | Recommended Fix |
|---|---|---|---|---|
| P0 | Security | Brute-force protection uses in-memory dict, not Redis; lost on restart and breaks across workers | routers/auth.py:36-37 | Move `_failed_attempts` and `_otp_attempts` to Redis with TTL |
| P0 | Security | Static upload directories mounted publicly without authentication | main.py:286,291 | Add authenticated endpoint or signed URLs for `/uploads` and `/static` |
| P0 | Security | `.env.example` still contains weak defaults: `ADMIN_PASSWORD=admin123`, placeholder JWT secret | .env.example:12,17 | Replace placeholders with strong random values; add `.env` to `.gitignore` if missing |
| P0 | Security | `ALLOW_SQLITE_FALLBACK=true` by default — production could silently use SQLite | database.py:11 | Default to `false`; require explicit opt-in for SQLite fallback |
| P1 | Security | CORS allows `*` in non-production (line 298), which is acceptable for dev but should be explicit per environment | main.py:298-302 | Keep `*` only for `development`; require explicit origins for `staging` |
| P1 | Performance | No global request timeout middleware — slow clients can hold connections indefinitely | main.py | Add `TimeoutMiddleware` with read/connect/write timeouts |
| P1 | Observability | No OpenTelemetry / distributed tracing — request IDs exist but are not propagated to downstream services | main.py:326 | Add OTLP export or propagate `X-Request-ID` to DB/Redis logs |
| P1 | Error Handling | Global exception handler returns `str(exc)` in non-production — may leak internal details | main.py:352 | Return sanitized error envelope with `error_id` in all environments |
| P2 | Code Quality | `models.py` is monolithic (2700+ lines) — hard to navigate and maintain | models.py | Split into domain-specific files: `user_models.py`, `payroll_models.py`, etc. |

| P3 | Testing | pytest suite exists but no coverage threshold enforcement | pytest.ini | Add `--cov-fail-under=80` to CI |
| P3 | Performance | `Database initialized successfully` logged at INFO for every startup — noisy in production | database.py | Downgrade to DEBUG or log only on schema change |

BACKEND POSITIVES
-----------------
- Production config validation with fail-fast on missing JWT/DB/CORS
- Rate limiting middleware with Redis backing
- Request ID, security headers, tenant context middleware
- Structured logging via structlog
- Read replica support via `READ_REPLICA_URL`
- Connection pooling with `pool_pre_ping` and timeouts
- Audit logging setup in lifespan
- Selfie/document retention background jobs

5. CROSS-CUTTING RECOMMENDATIONS
================================================================================

1. SHARED AUTH CLIENT
   Extract the axios + refresh token + permission logic into a shared
   `@hrms/auth-client` package consumed by web, mobile, and tenant hub.
   This eliminates duplication and ensures consistent security behavior.

2. SECRETS MANAGEMENT
   - Move all secrets out of `.env` and `.env.example`
   - Use EAS Secrets (mobile), Vercel/Render env vars (web), and
     Docker Secrets / AWS Secrets Manager (backend)
   - Rotate `JWT_SECRET_KEY`, `ADMIN_PASSWORD`, `SENTRY_DSN` immediately

3. TESTING STRATEGY
   - Backend: add pytest-cov with 80% threshold; focus on auth, payroll,
     attendance, and leave endpoints
   - Web: expand beyond utility tests; add component tests for AuthContext,
     RoleRouter, and critical admin pages
   - Mobile: add Jest tests for offlineSync, auth context, and API interceptors
   - Tenant Hub: add smoke tests for login and tenant CRUD

4. DEPLOYMENT HARDENING
   - Enable HTTPS everywhere (TLS termination at load balancer)
   - Add HSTS header
   - Set `secure`, `httpOnly`, `SameSite=Strict` on all cookies
   - Add WAF rules for SQL injection and XSS
   - Enable database connection SSL (`sslmode=require`)
   - Add database backup automation with point-in-time recovery

5. MONITORING & OBSERVABILITY
   - Backend: add OpenTelemetry tracing with Jaeger/Zipkin
   - Frontends: add Sentry session replay and performance monitoring
   - Mobile: add Firebase Crashlytics or Sentry native SDK
   - Add synthetic uptime checks for `/health/ready`
   - Set up PagerDuty/OpsGenie alerts for 5xx spikes

6. PERFORMANCE
   - Backend: add database query profiling; fix N+1 queries in employee/attendance endpoints
   - Web: implement route-based code splitting; add resource hints (`preload`, `prefetch`)
   - Mobile: implement image caching and list virtualization; reduce bundle size
   - All: add CDN for static assets and uploads
